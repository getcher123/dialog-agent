# Betancourt Document Consultant

Изолированный текстовый пилот в ветке `feature/betancourt`. Существующие голосовые backend/frontend проекта не изменяются. Приватный исходник, карточки, предметные тесты и отчёты не входят в Git или GitHub Pages.

## Архитектура

`GitHub Pages /betancourt/ -> HTTPS gateway -> private Flowise -> Qdrant + OpenAI`.

Шлюз не занимается RAG: проверяет код приглашения, лимиты и форму запроса, вызывает один фиксированный поток и возвращает только `answer` и `sources`. Поток: OpenAI embeddings -> Qdrant retriever -> Conversational Retrieval QA -> OpenAI. Memory-узла нет; gateway не передаёт `chatId`, `history` или `overrideConfig`. Проверено: каждый запрос получает новый контекст, одна embedding-операция и одна генерация. Flowise сохраняет сообщения в своей закрытой SQLite, но не использует их как память следующих запросов.

Параметры: `text-embedding-3-small`, 1536, Cosine, top-k 8; `gpt-4.1-mini-2025-04-14`, temperature 0, максимум 1000 выходных токенов. Повторы SDK отключены. `flowise/chatflow.json` экспортирован из сохранённого и испытанного живого потока, credentials удалены. Системный промпт: `flowise/prompt.txt`.

Испытанные зависимости: Node 24 для gateway; Qdrant 1.17.0; Flowise Docker по digest в `flowise/Dockerfile` (внутри пакет 3.1.2, Node 20.20.2). Registry tag `3.1.4` не совпадал с версией внутри образа, поэтому используется digest. Исправлена несовместимость `connect-sqlite3`: закреплена 0.9.15. `disable-retries.mjs` адресно отключает скрытые повторы двух OpenAI-узлов и завершает сборку ошибкой при изменении ожидаемого кода.

## Локальный Запуск

Нужны Node 24, Docker Compose, Python 3.10+ с venv/pip и приватный пакет владельца. Рабочая директория всех команд ниже: `betancourt/`.

1. Разместить приватные `kb/`, `tests/questions.jsonl`, `tests/test_kb.py`, `DELIVERY.md` вне Git. Единственный редактируемый источник индекса: `kb/cards.jsonl`.
2. Подготовить `.env` по `.env.example`. `PILOT_TOKEN` генерируется из 32 случайных байтов; он не равен ключу Flowise. Для локального браузера установить `PAGES_ORIGIN=http://127.0.0.1:3310`. Не включать чат до настройки потока.
3. Установить SDK: `python3 -m venv .venv`, затем `.venv/bin/pip install -r requirements.txt`. Если venv находится иначе, передать `PYTHON=/absolute/path/to/python`.
4. Запустить сервисы, индексировать данные, импортировать поток и привязать credentials по инструкции ниже. После изменения `.env` пересоздать gateway: `docker compose up -d --no-deps gateway`.

Четыре основные команды:

```bash
make check  # 15 gateway-тестов и 22 приватных проверки KB; без оплачиваемых API
make up     # Flowise, gateway, локальный Qdrant; сохраняет volumes
make index  # оплачиваемая индексация только новой версии, без автосплиттера
make smoke  # короткий live-прогон, нужны приватные questions.jsonl и токен
```

`node tools/smoke.mjs --all` выполняет все 20 вопросов с учётом лимита 5/IP/минуту. Ответы сохраняются только в игнорируемом `reports/`. HTTP 200 не является семантической приёмкой: результаты необходимо сверить с критериями вопросов и источником. `make check` без приватного пакета ожидаемо не может проверить KB; публичный CI запускает отдельно gateway-тесты.

Адреса локального стенда: UI `http://127.0.0.1:3310/betancourt/`, gateway health `http://127.0.0.1:3310/betancourt/healthz`, Flowise `http://127.0.0.1:3301`, Qdrant `http://127.0.0.1:6333`. Порты опубликованы только на loopback. Остановка: `docker compose down` без `-v`; это сохраняет данные.

## Восстановление Flowise

Открыть локальный UI, зарегистрировать одного владельца, импортировать `flowise/chatflow.json`. Создать OpenAI credential и назначить его обоим OpenAI-узлам. Указать реальный Qdrant URL (`http://qdrant:6333` внутри локального Compose), ключ при необходимости и коллекцию из `kb/index-state.json`. У документа/загрузчиков нет подключений: готовые карточки повторно не разбиваются.

Создать отдельный API key с правом `chatflows:predict`, назначить его потоку; публичный доступ и uploads не включать. Указать реальные `FLOWISE_FLOW_ID` и `FLOWISE_API_KEY` в gateway `.env`, установить `CHAT_ENABLED=true`, пересоздать gateway. Поле Return Source Documents должно быть включено. Не связывать узел памяти и не добавлять постоянный session ID.

Первоначальная настройка выполнена через локальный административный API Flowise; это не сервис автоматического bootstrap. Постоянный volume `flowise_data` содержит БД, credentials и ключ шифрования. Его резервная копия приватна. Для восстановления нужны и БД, и ключ шифрования, не только публичный JSON потока. Проверить права записи пользователя uid 1000 в `/data`.

## Amvera И Pages

Деплой Amvera требует действующей авторизации и разрешённых ресурсов в `waw0`. Рабочая конфигурация существующего голосового приложения не заменяется. На момент подготовки доступ к API Amvera возвращал 401; публичный backend не объявляется запущенным.

Для загрузки gateway/Flowise подготовлены allowlist-пакеты исходников без данных и секретов:

```bash
node tools/package-amvera.mjs gateway /tmp/betancourt-gateway-source
node tools/package-amvera.mjs flowise /tmp/betancourt-flowise-source
```

В каждом выходном каталоге находится применимый `amvera.yaml`. Gateway слушает 3000, `HOST=0.0.0.0`, одна реплика. Flowise требует постоянный `/data`, `DATABASE_PATH=/data`, `SECRETKEY_PATH=/data`, `BLOB_STORAGE_PATH=/data/storage`, `LOG_PATH=/data/logs`, `PORT=3000`, `DEBUG=false`, `DISABLE_FLOWISE_TELEMETRY=true`. Flowise и Qdrant не должны иметь публичного ingress. Реальные внутренние адреса берутся из настроек разрешённых проектов, не из предположения о названии. Qdrant/индекс нужно перенести отдельно; Docker-сборка их не содержит и не индексирует при рестарте. Создание дополнительных платных проектов не автоматизировано.

Gateway получает только `FLOWISE_URL`, `FLOWISE_FLOW_ID`, `FLOWISE_API_KEY`, `PILOT_TOKEN`, `CHAT_ENABLED`, `PAGES_ORIGIN`, `TRUSTED_PROXY_CIDRS`. OpenAI credential остаётся в Flowise. Для Pages origin: `https://getcher123.github.io`. HTTPS обеспечивает Amvera; доверие к `X-Forwarded-For` включается только после проверки настоящих адресов proxy. Пустой список безопасно объединяет посетителей за proxy в один лимит, а не доверяет поддельному IP.

Сетевая схема платформы: [официальная документация Amvera](https://docs.amvera.ru/applications/configuration/network.html). При восстановлении сначала отключить gateway, привязать приватную БД/поток и выполнить live-проверки; только затем включать доступ тестировщикам.

Pages-маршрут: `https://getcher123.github.io/dialog-agent/betancourt/`. Workflow этой ветки собирает основной frontend из `main` и добавляет только четыре публичных файла консультанта. `BETANCOURT_API_BASE` в GitHub repository variables должен быть реальным HTTPS-адресом gateway с `/betancourt`, без `/api/chat`. Пока адрес пуст, страница явно показывает недоступность сервера и не принимает код. Секретов в Pages нет.

Важно: общий workflow должен попасть в `main` отдельным инфраструктурным изменением, иначе старый deploy из `main` сотрёт дополнительный маршрут. Ветка с кодом консультанта остаётся отдельной. Не запускать старый workflow основного сайта до принятия этой настройки.

## Обновление И Ограничения

Новая KB: правка только `cards.jsonl` -> `make check` -> `make index` -> выключить чат -> выбрать новую проверенную коллекцию в Flowise -> smoke -> включить. Индексация использует UUIDv5, проверяет размер/метаданные/ID и пропускает полностью совпадающий индекс. Частичная загрузка может повторно оплатить embeddings всех карточек; это явно выводится. Старые коллекции автоматически не удаляются. Изменение KB, модели или общего промпта требует повторной предметной приёмки.

Аварийное выключение: `CHAT_ENABLED=false` и перезапуск gateway; `/healthz` остаётся доступным. Откат: выключить чат, вернуть согласованный прошлый flow/коллекцию и проверить; при отсутствии прежнего релиза оставить выключенным. Не откатывать чужую БД или основной голосовой сервис.

Защита: body 8 KiB, message 2000 символов, timeout 60 секунд, 2 одновременных запроса, 30/минуту суммарно, 5/IP/минуту. Счётчики в памяти одной реплики сбрасываются при рестарте и не являются денежным hard cap. Отключение клиента прекращает ожидание gateway, но отмена обработки у провайдера не гарантирована. Для пилота требуется наблюдение за расходами и ограниченное окно тестирования.

UI хранит код только в текущей странице, выводит модельный текст через `textContent`, показывает полные найденные карточки без усечения отрицаний. Очистка диалога в браузере не удаляет закрытые технические записи Flowise. Ответы не подтверждают текущие цены, наличие, сроки или актуальность правовых оснований.
